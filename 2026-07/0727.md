# Pydantic 검증 심화: Field·Literal·field_validator (04_validation/main.py)

단순 `dict`와 Pydantic 모델의 차이를 비교하고, Path·Query·Body 각각에 타입과 범위 제약을 선언해 잘못된 요청을 핸들러 실행 전에 차단.

```python
class ProductCreate(BaseModel):
    model_config = ConfigDict(extra="forbid")

    name: str = Field(min_length=2, max_length=50)
    price: float = Field(gt=0, le=1_000_000)
    category: Literal["book", "course", "tool"]
    tags: list[str] = Field(default_factory=list, max_length=5)

    @field_validator("name")
    @classmethod
    def normalized_name(cls, value: str) -> str:
        normalized = value.strip()
        if not normalized:
            raise ValueError("상품명은 공백만 입력할 수 없습니다.")
        if "무료" in normalized:
            raise ValueError("상품명에는 '무료'를 사용할 수 없습니다.")
        return normalized
```

- `/examples/raw`처럼 Body를 `dict`로 받으면 내부 필드의 타입·필수 여부·범위를 자동 검증하지 않지만, `ProductCreate`를 사용하면 선언한 조건에 맞지 않는 요청은 FastAPI가 422로 응답한다.
- `ConfigDict(extra="forbid")`는 모델에 정의되지 않은 추가 필드를 조용히 버리지 않고 오류로 처리하고, `Literal`은 별도 Enum 없이 `book`·`course`·`tool`만 허용한다.
- `field_validator`는 단순 제약으로 표현하기 어려운 업무 규칙을 검사한다. 여기서는 상품명 앞뒤 공백을 제거하고, 공백뿐인 이름이나 `"무료"`가 포함된 이름을 거절한다.
- `Path(ge=1, le=9999)`로 경로 변수 범위를 제한하고, `Query(alias="item-query", min_length=2, max_length=20)`로 Python 변수명과 실제 쿼리 이름을 다르게 지정할 수 있다.
- `/search`의 정규식 `pattern`은 영문·숫자·한글만 허용하므로 특수문자가 섞인 검색어는 함수에 도달하기 전에 검증 오류가 난다.

# response_model과 HTTPException으로 안전한 응답 만들기 (05_response_error/main.py)

서버 내부 데이터와 외부에 공개할 응답을 분리하고, 조회 실패를 일관된 HTTP 에러로 변환.

```python
class UserResponse(BaseModel):
    id: int
    username: str
    display_name: str

def find_user_or_404(user_id: int) -> dict:
    user = users.get(user_id)
    if user is None:
        raise HTTPException(status_code=404, detail="사용자를 찾을 수 없습니다.")
    return user

@app.get("/users/{user_id}", response_model=UserResponse)
async def get_user(user_id: int) -> dict:
    return find_user_or_404(user_id)
```

- 내부 `users`에는 `password`가 있지만 `response_model=UserResponse`에 그 필드가 없으므로 실제 응답에서는 자동으로 제외된다. 응답 모델은 문서화뿐 아니라 정보 노출 방지용 출력 필터 역할도 한다.
- 존재하지 않는 사용자는 `HTTPException(status_code=404, ...)`을 발생시키며, FastAPI가 이를 `{"detail": "..."}` 형태의 JSON 응답으로 변환한다.
- 조회와 404 처리를 `find_user_or_404()`에 모아 엔드포인트마다 반복되는 조건문을 줄였다.
- `/users`에서는 `Response` 객체를 받아 `X-Total-Count` 헤더를 추가한다. Body의 구조는 `response_model`, 부가 메타데이터는 응답 헤더로 각각 전달할 수 있다.

# REST 방식의 Task 조회·수정 (06_rest_crud/main.py)

Task 자원에 목록/단건 조회와 PUT·PATCH 수정을 구현하면서 HTTP Method별 의미와 요청 모델 분리 방법을 확인.

```python
@app.put("/api/v1/tasks/{task_id}", response_model=TaskResponse)
def replace_task(task_id: int, request: TaskReplace) -> TaskResponse:
    find_task_or_404(task_id)
    replaced = TaskResponse(id=task_id, **request.model_dump())
    tasks[task_id] = replaced
    return replaced

@app.patch("/api/v1/tasks/{task_id}", response_model=TaskResponse)
def update_task(task_id: int, request: TaskUpdate) -> TaskResponse:
    task = find_task_or_404(task_id)
    changed_fields = request.model_dump(exclude_unset=True)
    updated = task.model_copy(update=changed_fields)
    tasks[task_id] = updated
    return updated
```

- 목록 조회는 `completed`, `priority`, `keyword` 쿼리를 선택적으로 받아 순서대로 필터링한다. 값이 전달되지 않은 조건은 적용하지 않는다.
- `TaskResponse`, `TaskReplace`, `TaskUpdate`를 분리해 응답·전체 교체·부분 수정의 요구사항을 각 스키마에 표현한다.
- PUT은 `id`만 유지하고 나머지 자원 표현 전체를 `TaskReplace`의 값으로 교체하므로 모든 필드가 필수다.
- PATCH의 모든 필드는 선택 사항이며, `model_dump(exclude_unset=True)`로 클라이언트가 실제 전송한 필드만 추출한 뒤 `model_copy(update=...)`로 기존 모델을 갱신한다. 이를 통해 보내지 않은 값과 명시적으로 보낸 `null`을 구분할 수 있다.
- 저장소는 메모리 `dict`이므로 서버를 재시작하면 수정 내용이 사라진다. 이 단계의 목적은 DB 연결보다 REST 요청·응답 설계에 있다.

# APIRouter 모듈화와 OpenAPI 문서 구성 (D_07_router_openapi)

학생과 강좌 기능을 각각 별도 Router로 분리하고, 공통 스키마와 애플리케이션 진입점을 조립해 규모가 커져도 관리하기 쉬운 구조로 변경.

```python
app = FastAPI(
    title="Router and OpenAPI",
    description="students와 courses router를 하나의 API로 조립",
    version="1.0.0",
    openapi_tags=[
        {"name": "system", "description": "서버 상태 확인"},
        {"name": "students", "description": "학생 API"},
        {"name": "courses", "description": "강좌 조회"},
    ],
)

app.include_router(courses.router, prefix="/api/v1")
app.include_router(students.router, prefix="/api/v1")
```

- `routers/courses.py`와 `routers/students.py`는 각 도메인의 URL·핸들러·저장 데이터를 담당하고, `schemas.py`는 여러 Router가 공유하는 Pydantic 모델을 모아둔다.
- Router 자체의 prefix(`/courses`, `/students`)와 `include_router()`의 prefix(`/api/v1`)가 합쳐져 최종 URL은 `/api/v1/courses`, `/api/v1/students`가 된다.
- `tags`는 `/docs`에서 관련 API를 그룹화하고, 앱의 `title`·`description`·`version`·`openapi_tags`는 자동 생성되는 OpenAPI 문서의 설명을 풍부하게 만든다.
- `Level = Literal["beginner", "intermediate"]`를 공통 타입으로 재사용해 학생과 강좌의 레벨 값이 같은 규칙을 따르도록 했다.
- `/health`는 비즈니스 기능과 분리된 서버 상태 확인용 엔드포인트로, 애플리케이션과 Router가 정상 조립됐는지 빠르게 확인할 수 있다.

# pathlib 기반의 안전한 로컬 파일 입출력 (D_08_fileio/L_fileio/main.py)

문자열 경로 조합 대신 `pathlib.Path`를 사용해 텍스트 읽기·쓰기와 바이너리 복사를 구현하고, 허용된 데이터 폴더 밖으로 나가는 경로를 차단.

```python
BASE_DIR = Path(__file__).resolve().parent
DATA_DIR = BASE_DIR / "data"

def safe_data_path(filename: str) -> Path:
    candidate = (DATA_DIR / filename).resolve()
    if DATA_DIR.resolve() not in candidate.parents:
        raise ValueError("data폴더 밖의 경로는 사용할 수 없습니다.")
    return candidate
```

- `__file__` 기준으로 절대 경로를 만들기 때문에 프로그램을 어느 디렉터리에서 실행해도 동일한 `data` 폴더를 사용한다.
- 사용자 입력을 바로 파일 경로로 쓰지 않고 `resolve()`한 결과가 `DATA_DIR`의 하위인지 검사해 `../`를 이용한 경로 이탈(Path Traversal)을 막는다.
- `read_text()`·`write_text()`는 UTF-8 인코딩을 명시하고, `mkdir(parents=True, exist_ok=True)`로 저장 폴더가 없어도 생성한다.
- 바이너리 파일은 문자열로 디코딩하지 않고 `read_bytes()`와 `write_bytes()`를 이용해 그대로 복사한다.

# Form·UploadFile과 파일 저장 API (D_08_fileio/fastapi_upload/main.py)

JSON Body가 아닌 HTML Form과 `multipart/form-data`를 받고, 업로드 파일의 형식·확장자·크기를 검증한 뒤 UUID 기반 이름과 JSON 메타데이터로 저장.

```python
@app.post("/api/v1/files", response_model=FileInfo, status_code=201)
async def upload_file(
    file: Annotated[UploadFile, File()],
    description: Annotated[str, Form(min_length=1, max_length=100)]
) -> FileInfo:
    content_type = file.content_type or "application/octet-stream"
    suffix = ALLOWD_CONTENT_TYPES_.get(content_type)
    original_name = Path(file.filename or "").name

    if suffix is None or Path(original_name).suffix.lower() != suffix:
        raise HTTPException(status_code=415, detail="확장자와 형식이 일치하는 txt/pdf만 허용합니다.")

    content = await file.read(MAX_FILE_SIZE + 1)
    if len(content) > MAX_FILE_SIZE:
        raise HTTPException(status_code=413, detail="파일은 1MB 이하여야 합니다.")
```

- `/login`은 `Form()`으로 username과 password를 받고, 파일 엔드포인트는 `File()`과 `Form()`을 함께 선언해 하나의 multipart 요청에서 파일과 설명을 받는다.
- `UploadFile`은 업로드 파일명·Content-Type과 비동기 읽기 인터페이스를 제공한다.
- 허용 형식은 txt와 pdf로 제한하며, Content-Type과 실제 파일명 확장자가 서로 일치하지 않으면 415(Unsupported Media Type)를 반환한다.
- 최대 크기보다 1바이트 더 읽은 뒤 길이를 비교하면 제한을 초과했는지 판별할 수 있다. 1MB를 넘으면 413(Payload Too Large)을 반환한다.
- 원본 파일명은 `Path(...).name`으로 디렉터리 부분을 제거하고, 실제 저장 이름은 UUID로 생성해 이름 충돌과 임의 경로 사용을 줄인다.
- 파일 본문과 별도로 같은 UUID의 JSON 파일에 원본명·형식·크기·설명·저장명을 기록한다. `ensure_ascii=False`로 한글 메타데이터도 읽기 쉽게 보존한다.
- `metadata_path()`는 외부에서 받은 ID가 올바른 UUID인지 먼저 검증해 임의 문자열을 파일 경로로 사용하는 것을 방지한다.

# Spring Boot에서 FastAPI 호출하기 (D_09_spring_integration)

FastAPI를 별도 파일 서비스로 실행하고, Spring Boot가 Python 함수를 직접 부르는 대신 HTTP 클라이언트로 요청하는 서비스 간 연동 구조를 구현.

```java
public HealthResponse checkHealth() {
    return restClient.get()
            .uri("/health")
            .retrieve()
            .body(HealthResponse.class);
}

@GetMapping("/health")
public ResponseEntity<?> health() {
    try {
        return ResponseEntity.ok(fastApiFileClient.checkHealth());
    } catch (RestClientException e) {
        return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE)
                .body(Map.of(
                        "code", "FASTAPI_UNAVAILABLE",
                        "message", "FastAPI서버에 연결할 수 없습니다."
                ));
    }
}
```

- FastAPI는 8002번 포트에서 `/health`를 제공하고, Spring Boot는 8080번 포트에서 클라이언트 요청을 받는다. `application.yaml`의 `fastapi.url`로 Python 서비스 주소를 코드 밖에서 설정한다.
- `FastApiFileClient`는 Spring의 `RestClient`에 base URL을 설정하고 `/health`를 GET으로 호출해 JSON 응답을 Java record로 역직렬화한다.
- `@JsonNaming(PropertyNamingStrategies.SnakeCaseStrategy.class)` 덕분에 FastAPI의 `snake_case` JSON 필드와 Java의 `camelCase` 필드를 자연스럽게 매핑할 수 있다.
- `FileBridgeController`의 `/api/files/health`는 프론트엔드가 FastAPI에 직접 접근하지 않고 Spring을 경유하도록 만든 브리지 엔드포인트다.
- FastAPI가 꺼져 있거나 통신에 실패해 `RestClientException`이 발생하면 Spring은 내부 오류를 그대로 노출하지 않고 503(Service Unavailable)과 일관된 에러 코드 `FASTAPI_UNAVAILABLE`을 반환한다.
- `@CrossOrigin`은 개발 프론트엔드 주소인 `localhost:3000`과 `localhost:5173`의 브라우저 요청을 허용한다.
- Spring과 FastAPI는 서로 다른 프로세스·언어로 실행되지만 HTTP와 JSON이라는 공통 계약으로 느슨하게 결합된다. 한쪽 구현을 바꾸더라도 URL과 요청·응답 스키마를 유지하면 다른 쪽의 영향이 줄어든다.

# 전체 흐름 정리

1. Pydantic과 FastAPI 선언으로 Path·Query·Body 입력을 검증한다.
2. `response_model`과 `HTTPException`으로 공개할 데이터와 HTTP 오류 형식을 통제한다.
3. PUT·PATCH의 의미에 맞춰 전체 교체 모델과 부분 수정 모델을 분리한다.
4. `APIRouter`와 공통 schemas 모듈로 기능을 도메인별로 나누고 OpenAPI 문서를 구성한다.
5. `pathlib`과 안전한 경로 검사로 서버 파일을 읽고 쓰며, 업로드 형식·크기·이름을 검증한다.
6. 파일과 메타데이터를 저장하는 FastAPI 서비스를 만들고, Spring Boot가 `RestClient`로 이를 HTTP 호출한다.
7. Spring은 외부 클라이언트와 FastAPI 사이의 브리지 역할을 하며, 하위 서비스 장애를 503 응답으로 변환한다.
