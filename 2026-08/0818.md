# Grafana CloudWatch 연동과 문의 챗봇 스크롤 버그 수정

Grafana에 CloudWatch 데이터소스와 ALB 모니터링 패널을 추가해 인프라 지표까지 한 화면에서 볼 수 있게 했고, Elastic Beanstalk 헬스 리포팅을 강화했다. 프런트에서는 문의 챗봇의 스크롤 자동 이동 로직에서 버그를 발견해 수정했다.

---

# 1. Grafana CloudWatch 데이터소스 추가

기존에는 Grafana가 Prometheus 데이터소스만 물고 있어서 애플리케이션 지표만 볼 수 있었다. ALB, Target Group처럼 AWS 인프라 자체의 지표는 CloudWatch에만 있기 때문에 별도 데이터소스를 추가했다.

```yaml
apiVersion: 1

datasources:
  - name: CloudWatch
    uid: cloudwatch
    type: cloudwatch
    access: proxy

    jsonData:
      authType: default
      defaultRegion: ap-northeast-2

    editable: false
```

`authType: default`로 두면 Grafana 컨테이너가 실행 중인 EC2의 IAM 역할 자격 증명을 그대로 사용한다. 별도로 Access Key를 파일이나 환경변수에 넣지 않아도 되므로 자격 증명 관리 포인트가 늘어나지 않는다.

---

# 2. ALB 모니터링 패널 추가

CloudWatch 데이터소스를 붙인 뒤 Grafana 대시보드에 ALB 관련 패널 3개를 추가했다.

| 패널 | Metric | Statistic |
| --- | --- | --- |
| ALB 요청 수 | `RequestCount` | Sum |
| ALB 평균 응답시간 | `TargetResponseTime` | Average |
| ALB 정상 타겟 수 | `HealthyHostCount` | Average |

Prometheus 지표는 애플리케이션 내부(HTTP 처리 시간, JVM 상태 등)를 보여주지만, ALB 지표는 로드밸런서 관점에서 실제로 얼마나 많은 요청이 들어왔고 타겟이 몇 개나 정상인지를 보여준다. 두 관점을 같은 대시보드에서 함께 보면 "애플리케이션은 정상인데 ALB가 트래픽을 못 넘겨주는" 것 같은 경계 구간 문제도 구분할 수 있다.

---

# 3. Elastic Beanstalk CloudWatch Logs와 Health Reporting

Beanstalk 인스턴스 로그를 CloudWatch Logs로 스트리밍하도록 설정을 추가했다.

```yaml
option_settings:
  aws:elasticbeanstalk:cloudwatch:logs:
    StreamLogs: true
    DeleteOnTerminate: false
    RetentionInDays: 14
```

`DeleteOnTerminate: false`로 두면 환경을 종료해도 로그 그룹이 바로 삭제되지 않아서, 배포 후 인스턴스가 재시작되거나 환경이 재생성되더라도 이전 로그를 계속 확인할 수 있다.

Enhanced Health Reporting도 함께 켰다.

```yaml
option_settings:
  aws:elasticbeanstalk:healthreporting:system:
    SystemType: enhanced
    ConfigDocument:
      CloudWatchMetrics:
        Environment: {}
        Instance: {}
      Version: 1
```

Basic Health는 단순히 Up/Down만 보여주지만, Enhanced Health는 요청 처리량, 응답 지연, OS 레벨 지표까지 CloudWatch 네임스페이스로 함께 보낸다. 배포 워크플로우의 압축 대상에 `.ebextensions`가 빠져 있어서 설정이 실제로는 적용되지 않는 문제가 있었는데, `deploy.zip` 생성 스크립트에 `.ebextensions` 복사 단계를 추가해서 해결했다.

```yaml
mkdir deploy
cp Dockerrun.aws.json deploy/
cp -r .ebextensions deploy/
cd deploy
zip -r deploy.zip .
```

`.ebextensions`는 Beanstalk이 배포 zip 루트에서 직접 찾는 디렉터리라, deploy 폴더 안에 넣는 걸 빠뜨리면 설정 파일 자체가 반영되지 않는다는 걸 이번에 확인했다.

# 4. 문의 챗봇 스크롤 자동 이동 버그

문의 챗봇에 새 메시지가 오면 채팅창이 자동으로 최신 메시지로 스크롤되도록 기능을 추가했는데, 처음 구현에서는 메시지 목록 맨 아래에 빈 `div`를 두고 `scrollIntoView`를 호출했다.

```jsx
const messagesEndRef = useRef(null);

useEffect(() => {
  messagesEndRef.current?.scrollIntoView({ block: 'end' });
}, [messages, sending]);
```

이 방식은 대화가 길어질 때 채팅창 내부는 물론 모달 바깥의 페이지 스크롤까지 함께 움직이는 문제가 있었다. `scrollIntoView`는 대상 요소가 보이도록 조상 스크롤 컨테이너를 전부 훑으면서 스크롤시키기 때문에, 모달 바깥에 스크롤 가능한 레이아웃이 있으면 의도치 않게 페이지 자체도 흔들렸다.

메시지 목록을 감싸는 컨테이너에 직접 ref를 걸고, `scrollTop`을 `scrollHeight`로 맞추는 방식으로 바꿔서 해결했다.

```jsx
const messagesListRef = useRef(null);

useEffect(() => {
  const list = messagesListRef.current;
  if (list) list.scrollTop = list.scrollHeight;
}, [messages, sending]);
```

이렇게 하면 스크롤 대상이 채팅 목록 컨테이너 하나로 명확해져서 페이지 전체가 아니라 채팅창 내부만 스크롤된다.

---

# 5. 정리

- Grafana에 CloudWatch 데이터소스를 추가해 ALB 지표(요청 수, 응답시간, 정상 타겟 수)를 대시보드에 반영했다.
- IAM 역할 기반 인증(`authType: default`)으로 Grafana에 별도 Access Key를 두지 않았다.
- Elastic Beanstalk CloudWatch Logs와 Enhanced Health Reporting을 켰고, `.ebextensions`가 배포 zip에서 빠지는 문제를 스크립트 수정으로 해결했다.
- `scrollIntoView`가 조상 스크롤 컨테이너까지 건드리는 문제를 확인하고, 스크롤 대상 컨테이너에 직접 `scrollTop`을 지정하는 방식으로 바꿨다.
