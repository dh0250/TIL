# 시네로그 영화 리뷰 아카이브 서비스 전체 설계

시네로그는 TMDB 영화 메타데이터를 기반으로 사용자가 영화를 탐색하고, 보고 싶은 영화를 찜하고, 감상한 영화에 별점과 리뷰를 남기는 서비스다. Spring Boot와 React를 이용해 영화 데이터 수집부터 검색, 인증, 리뷰 평점 관리, 반응형 화면까지 하나의 서비스로 구성한다.

---

# 1. 서비스 목표와 기능 범위

비회원과 회원의 기능을 다음과 같이 구분한다.

```text
비회원
- 영화 목록과 상세 정보 조회
- 제목과 원제 검색
- 장르와 신작 조건 조회
- 다른 회원이 작성한 리뷰 조회

회원
- 비회원 기능 전체
- 보고 싶은 영화 찜 추가와 취소
- 별점과 리뷰 작성·수정·삭제
- 내 찜 목록과 내 리뷰 조회
```

별점은 0.5점부터 5.0점까지 0.5점 단위로 입력한다. 한 회원은 같은 영화에 활성 리뷰 하나만 작성할 수 있으며, 본인이 작성한 리뷰만 수정하거나 삭제할 수 있다. 구독 결제, 배치 리포트, 회원 팔로우, 피드, 리뷰 좋아요와 개인화 추천은 MVP 범위에서 제외한다.

---

# 2. TMDB 영화 데이터 수집

데이터베이스에는 제목, 원제, 줄거리, 장르, 포스터 경로, 개봉일과 러닝타임 같은 순수 영화 메타데이터만 저장한다. TMDB의 평점과 투표 수는 저장하거나 화면에 노출하지 않는다. 서비스 평균 별점은 시네로그 회원이 작성한 리뷰만으로 계산한다.

초기 시딩에서는 장르를 먼저 저장하고, 국가 제한 없이 인기 영화 상위 25페이지에서 최대 500편을 수집한다. 영화의 TMDB 식별자에 유니크 제약을 적용해 중복 저장을 방지하고, 필요한 영화만 상세 API를 호출해 러닝타임을 보완한다.

```text
장르 API 호출
→ 인기 영화 최대 500편 조회
→ TMDB 식별자로 중복 확인
→ 신규 영화와 장르 관계 저장
→ 상세 API로 필요한 정보 보완
```

TMDB의 전체 검색 결과를 모두 저장하지 않고 서비스에서 실제로 탐색할 가능성이 높은 영화만 제한적으로 수집한다.

---

# 3. 주간 신작 동기화 스케줄러

매주 월요일 오전 3시에 최근 60일 이내 개봉한 한국 및 해외 영화를 조회한다. 결과는 TMDB 인기도가 높은 순으로 최대 5페이지, 100편까지만 확인한다. 인기도 값은 수집 대상의 우선순위를 정할 때만 사용하고 데이터베이스에는 저장하지 않는다.

```text
최근 60일 이내 개봉작 조회
→ 인기도순 최대 100편 선택
→ 신규 영화 저장
→ 기존 영화 메타데이터 비교
→ 변경된 항목만 갱신
```

이전 실행 실패나 TMDB 등록 지연으로 인한 누락을 줄이기 위해 매번 최근 60일 범위를 다시 조회한다. 이미 저장된 영화는 제목, 줄거리, 포스터, 개봉일, 러닝타임과 장르가 실제로 변경된 경우에만 갱신한다. 리뷰나 찜이 연결된 영화는 자동으로 삭제하지 않는다.

---

# 4. 백엔드와 도메인 설계

백엔드는 Java 21, Spring Boot, Spring MVC와 Spring Data JPA를 사용한다. 주요 도메인은 회원, 영화, 장르, 리뷰와 찜이다.

```text
Member 1 ─── N Review
Member 1 ─── N Watchlist
Movie  1 ─── N Review
Movie  1 ─── N Watchlist
Movie  N ─── M Genre
```

영화와 장르는 다대다 관계이므로 중간 테이블로 연결한다. 영화의 TMDB 식별자, 장르의 TMDB 장르 식별자, 회원과 영화의 찜 조합에는 각각 유니크 제약을 적용한다. 리뷰 작성·수정·삭제와 영화의 평균 별점·리뷰 수 갱신은 하나의 트랜잭션에서 처리해 데이터가 어긋나지 않도록 한다.

인증에는 Spring Security, OAuth2 소셜 로그인과 JWT를 사용할 예정이다. 영화 목록과 상세 및 리뷰 조회는 비회원에게도 허용하고, 찜과 리뷰 변경 API는 인증된 회원만 호출할 수 있도록 구분한다.

---

# 5. 영화 조회와 검색 설계

사용자는 영화 목록을 장르, 신작 여부, 개봉일과 최소 평점 등의 조건으로 조회할 수 있다. 정렬은 개봉일 최신순, 사용자 평점 높은 순과 리뷰 많은 순을 제공한다. 신작은 조회일을 기준으로 최근 90일 이내 개봉한 영화로 정의한다.

검색은 단계적으로 구현한다.

```text
1단계: PostgreSQL ILIKE로 제목과 줄거리 검색
2단계: pg_trgm으로 부분 일치와 유사 검색 개선
3단계: Elasticsearch와 Nori로 한국어 전문 검색
4단계: 동일 데이터와 검색어로 성능 비교
```

Elasticsearch를 적용하면 영화 제목과 줄거리뿐 아니라 리뷰 본문도 검색한다. 리뷰 본문이 일치한 경우에도 검색 결과는 리뷰가 아닌 영화 단위로 반환한다. PostgreSQL과 Elasticsearch의 응답 시간, 오타 허용, 형태소 분석과 검색 정확도를 비교해 전문 검색 도입 효과를 확인한다.

---

# 6. React 프론트엔드 구성

프론트엔드는 React, Vite, JavaScript와 React Router를 사용하는 SPA로 구성한다. 홈, 영화 둘러보기, 영화 목록, 영화 상세, 찜 목록, 로그인, 회원가입, 마이페이지와 내 리뷰 화면을 제공한다.

영화 탭에서는 한글 제목과 영문 원제를 검색하고 장르 필터를 함께 적용할 수 있다. 영화 카드를 선택하면 줄거리, 장르, 개봉일, 러닝타임, 서비스 평균 별점, 리뷰 수와 다른 회원의 리뷰를 확인한다. 로그인한 사용자는 영화를 찜하고 숫자 선택 목록에서 0.5점 단위의 별점을 선택해 리뷰를 작성한다.

마이페이지 상단에는 사용자 이름, 이메일과 회원정보 수정 버튼을 배치하고 내 찜과 내 리뷰 화면으로 이동하는 버튼을 제공한다. 실제 백엔드 인증을 연결하기 전에는 데모 로그인을 사용해 로그인 이후의 화면 흐름을 확인한다.

---

# 7. UI와 반응형 화면

전체 색상은 시네로그의 기존 분위기를 유지하고, 버튼과 카드는 단순하고 둥근 형태로 구성한다. 라이트 모드와 다크 모드를 제공하며 선택한 테마는 브라우저에 저장한다. 다크 모드에서는 배경뿐 아니라 제목, 본문과 버튼의 글자색도 함께 변경해 가독성을 유지한다.

```text
데스크톱 화면: 영화 카드 5열
중간 크기 화면: 영화 카드 3열
작은 화면: 영화 카드 2열
```

화면이 작아지면 카드가 오히려 커지지 않도록 열 개수를 단계적으로 변경한다. 모바일에서는 상단 메뉴를 없애는 대신 햄버거 메뉴로 전환하고, 로그인 후 페이지가 이동할 때는 항상 화면 맨 위에서 시작하도록 처리한다.

---

# 8. 개발 순서와 활용 계획

먼저 영화와 장르 엔티티, TMDB 초기 시딩을 구현하고 영화 목록과 상세 조회 API를 개발한다. 이후 OAuth2와 JWT 인증, 찜, 리뷰와 별점 기능을 연결한다. 다음으로 주간 신작 동기화 스케줄러와 PostgreSQL 검색을 완성하고 Elasticsearch를 추가해 검색 결과와 성능을 비교한다.

프론트엔드의 임시 영화 데이터와 데모 로그인은 백엔드 API가 준비되면 실제 영화 조회와 인증 요청으로 교체한다. 이후 통합 테스트, 검색 성능 측정과 배포를 진행해 영화 탐색, 찜, 리뷰, 별점과 데이터 동기화가 가능한 MVP를 완성한다.

---

# 9. 정리

- 시네로그는 영화 탐색, 찜, 별점과 리뷰 작성을 제공하는 영화 아카이브 서비스다.
- TMDB에서는 순수 영화 메타데이터만 저장하고 서비스 평점은 회원 리뷰로 계산한다.
- 초기 영화는 최대 500편, 주간 신작은 최근 60일 이내 인기 영화 최대 100편으로 제한한다.
- 신규 영화는 추가하고 기존 영화는 실제로 변경된 메타데이터만 갱신한다.
- Spring Boot와 PostgreSQL로 백엔드를 구성하고 OAuth2와 JWT로 회원을 인증한다.
- PostgreSQL과 Elasticsearch의 검색 결과와 성능을 비교한다.
- React와 Vite 기반 SPA에서 영화 검색, 상세, 찜, 리뷰와 마이페이지를 제공한다.
- 화면 크기에 따라 영화 카드를 5열, 3열과 2열로 배치하고 라이트·다크 모드를 지원한다.
