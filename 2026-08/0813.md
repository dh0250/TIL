# AWS 배포와 서비스 연동 점검

냉파마스터의 Spring Boot와 FastAPI를 Elastic Beanstalk에 배포하고, Amplify 프런트엔드와 운영 도메인을 연결하면서 환경변수, 보안 설정, 상태 확인 방법을 점검했다.

---

# 1. Elastic Beanstalk 환경변수

로컬의 `.env` 파일은 배포 서버에 자동으로 전달되지 않으므로 Elastic Beanstalk 환경 속성에 운영 값을 별도로 등록해야 한다.

| 애플리케이션 | 주요 설정 |
| --- | --- |
| Frontend | `BACKEND_URL`, 공개 클라이언트 키 |
| Spring Boot | DB, JWT, OAuth2, S3, Agent 연결 정보 |
| FastAPI | OpenAI, Backend 주소, Agent 인증 키 |

운영 환경에서는 localhost 대신 실제 도메인을 사용한다.

```plain text
Frontend → https://api.naengpa.com
Spring Boot → 배포된 FastAPI 주소
FastAPI → https://api.naengpa.com
```

OAuth2 리다이렉트 주소도 운영 도메인으로 맞춰야 한다.

```plain text
OAUTH2_REDIRECT_BASE_URL=https://api.naengpa.com
OAUTH2_FRONTEND_REDIRECT_URL=https://www.naengpa.com
```

# 2. Secrets Manager 연동

DB 비밀번호, JWT 비밀키, OAuth Client Secret처럼 노출되면 안 되는 값은 Secrets Manager에 저장했다.

Elastic Beanstalk에서 Secret을 환경변수로 연결할 때는 실제 값이 아니라 올바른 ARN을 지정해야 한다. JSON Secret의 특정 키를 사용한다면 Secret 구조와 환경변수 연결 방식이 일치해야 한다.

Elastic Beanstalk EC2 역할에는 `secretsmanager:GetSecretValue` 권한이 필요하다. ARN 오류, 권한 부족, JSON 형식 오류가 발생하면 배포가 중단될 수 있으므로 설정 수정 후 정상 버전을 다시 배포한다.

# 3. GitHub Actions 자동 배포

```plain text
main 반영
→ Gradle Build
→ Docker 이미지 생성
→ ECR Push
→ Dockerrun.aws.json 생성
→ Elastic Beanstalk 배포
```

필요한 Repository Secrets는 다음과 같다.

- `AWS_ACCESS_KEY_ID`
- `AWS_SECRET_ACCESS_KEY`
- `AWS_REGION`
- `EB_APP_NAME`
- `EB_ENV_NAME`

ECR Repository 이름과 Elastic Beanstalk 애플리케이션·환경 이름은 실제 AWS 리소스 이름과 정확히 일치해야 한다.

# 4. 배포 상태와 Health Check

Elastic Beanstalk의 `Degraded`, `Warning` 상태는 컨테이너 실행 실패, 잘못된 환경변수, Secret 조회 실패, Target Group Health Check 실패 등으로 발생할 수 있다.

- Spring Boot: Health endpoint와 Actuator 확인
- FastAPI: Nginx를 통한 `/health` 확인
- ALB: Target Group의 상태가 `Healthy`인지 확인
- Docker: `docker ps`, 컨테이너 로그 확인

컨테이너 포트가 외부에 직접 매핑되지 않아도 Elastic Beanstalk의 Nginx가 요청을 전달할 수 있다.

# 5. Spring Boot와 FastAPI 연동

```plain text
사용자 브라우저
→ Frontend
→ Spring Boot
→ FastAPI
→ OpenAI
```

운영 환경에서 `localhost`는 각 서버 자기 자신을 의미하므로 다른 애플리케이션 주소로 사용할 수 없다. Spring Boot와 FastAPI의 Base URL을 실제 내부 또는 운영 주소로 변경하고 관련 서비스를 재배포해야 한다.

---

# 6. AI 응답 시간 로그

장보기 AI와 문의 챗봇의 지연 구간을 확인하기 위해 FastAPI의 OpenAI 호출 시간을 기록했다.

```plain text
shopping OpenAI call elapsed_ms=...
inquiry OpenAI call elapsed_ms=...
```

로컬 테스트 결과 장보기 추천은 후보 데이터와 생성 결과가 많아 문의 챗봇보다 OpenAI 호출 시간이 길었다. 로그를 통해 프런트, Spring Boot, FastAPI, OpenAI 중 실제 병목 구간을 구분할 수 있다.

---

# 7. 정리

- 로컬 `.env`와 운영 환경변수는 별도로 관리한다.
- 민감한 값은 Secrets Manager에 저장하고 EC2 역할에 최소 조회 권한만 부여한다.
- 배포 실패 시 이벤트 메시지뿐 아니라 Docker와 Elastic Beanstalk 로그를 함께 확인한다.
- 서비스 간 주소에서 `localhost`를 사용하지 않는다.
- AI 호출 시간 로그로 느린 구간을 구분한다.
