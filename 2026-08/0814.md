# Prometheus와 Grafana 모니터링 서버 구축

Spring Boot와 FastAPI의 상태와 성능 지표를 수집하기 위해 별도의 Monitoring EC2에 Prometheus와 Grafana를 Docker Compose로 구성했다.

---

# 1. 모니터링 구조

```plain text
Spring Boot /actuator/prometheus ─┐
                                  ├→ Prometheus → Grafana
FastAPI /metrics ─────────────────┘
```

- Prometheus: 각 서버의 메트릭을 주기적으로 수집하고 저장
- Grafana: Prometheus 데이터를 대시보드로 시각화
- Monitoring EC2: Prometheus와 Grafana를 실행하는 별도 서버

Prometheus가 각 서버의 메트릭 주소를 주기적으로 조회하는 Pull 방식으로 동작한다.

---

# 2. 애플리케이션 메트릭 노출

Spring Boot에는 Actuator와 Micrometer Prometheus를 연결해 `/actuator/prometheus`를 노출했다. FastAPI에는 Prometheus Instrumentator를 연결해 `/metrics`를 노출했다.

두 서비스 모두 컨테이너 포트를 직접 호출하지 않고 각 호스트의 Nginx 80 포트를 통해 확인했다.

---

# 3. 네트워크와 Security Group

| 대상 | 포트 | Source |
| --- | --- | --- |
| Spring Boot Nginx | 80 | Monitoring SG |
| FastAPI Nginx | 80 | Monitoring SG |

```bash
curl http://SPRING_PRIVATE_IP/actuator/prometheus
curl http://FASTAPI_PRIVATE_IP/metrics
```

응답에 여러 Prometheus 지표가 출력되면 네트워크와 메트릭 노출이 정상이다.

---

# 4. Monitoring EC2 준비

Monitoring EC2에는 Docker와 Docker Compose를 설치하고 배포 디렉터리를 구성했다.

```plain text
/opt/naengpa-monitoring/
├── releases/
├── runtime/
└── current → releases/{Git SHA}
```

- `releases`: 버전별 모니터링 설정 보관
- `runtime`: Grafana 비밀번호 같은 런타임 파일 보관
- `current`: 현재 실행할 Release를 가리키는 심볼릭 링크

---

# 5. Monitoring Repository

```plain text
Monitoring/
├── compose.yaml
├── prometheus/
│   ├── prometheus.yml
│   └── rules/alerts.yml
└── grafana/
    └── provisioning/
        ├── datasources/prometheus.yml
        └── dashboards/
```

Prometheus에는 Spring Boot와 FastAPI Target을 등록하고 Grafana에는 Prometheus Data Source를 자동 등록하도록 설정했다. Grafana는 외부에 직접 공개하지 않고 `127.0.0.1:3000`에만 연결했다.

---

# 6. Grafana 비밀번호 관리

Grafana 관리자 비밀번호는 Secrets Manager에 저장했다. Monitoring EC2 역할에는 해당 Secret을 읽는 `secretsmanager:GetSecretValue` 권한을 추가했다.

조회한 비밀번호는 다음 런타임 파일에 저장하고 Docker Secret으로 전달했다.

```plain text
/opt/naengpa-monitoring/runtime/grafana_admin_password
```

Grafana 컨테이너 사용자가 파일을 읽을 수 있도록 소유권과 권한도 설정했다.

---

# 7. S3 Release 배포

```plain text
Git Repository
→ {Git SHA}.tar.gz
→ S3 monitoring/{Git SHA}.tar.gz
→ Monitoring EC2 releases/{Git SHA}
→ current 심볼릭 링크 변경
```

Git SHA를 버전으로 사용하면 실행 중인 설정 버전을 확인하고 이전 Release로 되돌리기 쉽다. macOS에서 압축할 때 생성되는 `._*` 파일은 Prometheus가 YAML로 잘못 읽을 수 있으므로 압축 시 제외해야 한다.

---

# 8. Docker Compose 실행과 오류 해결

```bash
sudo docker compose pull
sudo docker compose up -d
sudo docker compose ps
```

초기 실행에서 다음 문제를 해결했다.

- Prometheus: macOS `._alerts.yml` 파일로 YAML 파싱 실패
- Grafana: 관리자 비밀번호 파일 읽기 권한 부족

숨김 파일을 삭제하고 Grafana 컨테이너 사용자가 Secret 파일을 읽을 수 있도록 권한을 수정한 뒤 두 컨테이너가 정상 실행됐다.

---

# 9. 수집 상태 확인

```bash
sudo docker compose exec prometheus \
  wget -qO- http://localhost:9090/-/healthy
```

Prometheus Target API에서 `spring-prod`, `fastapi-prod`가 모두 `health: up`인 것을 확인했다. Grafana `/api/health`도 `HTTP 200`과 `database: ok`를 반환했다.

Grafana는 SSM Port Forwarding으로 접속한다.

```bash
aws ssm start-session \
  --target MONITORING_INSTANCE_ID \
  --document-name AWS-StartPortForwardingSession \
  --parameters '{"portNumber":["3000"],"localPortNumber":["3000"]}' \
  --region ap-northeast-2
```

세션을 유지한 상태에서 브라우저로 `http://localhost:3000`에 접속한다.

---

# 10. 정리

- Prometheus는 Spring Boot와 FastAPI의 메트릭을 Pull 방식으로 수집한다.
- 메트릭 포트는 인터넷에 공개하지 않고 Security Group 간 통신만 허용한다.
- Grafana는 외부에 직접 공개하지 않고 SSM Port Forwarding으로 접속한다.
- 비밀번호는 Secrets Manager에서 관리한다.
- Git SHA Release 구조로 설정 버전과 롤백 경로를 관리한다.
