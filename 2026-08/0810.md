# 문의 Q&A 챗봇을 위한 RAG 설계와 정책 문서 구축

냉파마스터 서비스 이용 방법을 답변하는 문의 Q&A 챗봇을 구현하기 위해 정책 문서를 정리하고, Spring Boot와 FastAPI를 분리한 RAG 구조를 설계했다. Spring Boot는 인증·데이터 저장·사용량 기록을 담당하고 FastAPI는 문서 검색과 OpenAI 답변 생성을 담당한다.

---

# 1. RAG란?

RAG(Retrieval-Augmented Generation)는 LLM이 바로 답변하기 전에 관련 문서를 검색하고, 검색 결과를 근거로 답변을 생성하는 방식이다.

```plain text
사용자 질문
→ 관련 정책 문서 검색
→ 검색된 문서 조각을 프롬프트에 포함
→ OpenAI 답변 생성
```

LLM 자체 지식만 사용하면 서비스 내부 정책을 정확히 알 수 없다. 회원 탈퇴, 사전재료 등록, 냉파 점수처럼 프로젝트 고유 규칙은 별도 정책 문서로 제공해야 한다.

---

# 2. 정책 문서와 청크

정책 문서는 서비스 기능별 Markdown 파일로 정리했다.

- 냉장고 및 유통기한
- 레시피 이용 방법
- 문의 등록과 답변
- 냉파 점수 및 통계
- 사전재료 등록 정책

문서 전체를 매번 LLM에 전달하면 불필요한 토큰이 많아진다. 문서를 작은 단위인 **청크(chunk)**로 나누고 질문과 관련된 청크만 검색한다.

초기 청크 크기는 약 1,200자를 기준으로 했지만, 짧은 문서는 한 개의 청크만 생길 수 있다. 글자 수만 기준으로 자르기보다 제목과 문단 경계를 우선하는 방식이 문맥 보존에 더 유리하다.

---

# 3. 데이터베이스 구성

문의 챗봇은 기존 AI 대화 테이블과 역할이 달라 전용 테이블을 사용했다.

| 테이블 | 역할 |
| --- | --- |
| `inquiry_knowledge_documents` | 정책 문서 원본과 상태 저장 |
| `inquiry_knowledge_chunks` | 검색 가능한 문서 조각 저장 |
| `inquiry_chat_sessions` | 회원별 챗봇 대화 세션 저장 |
| `inquiry_chat_messages` | 사용자 질문과 AI 답변 저장 |
| `llm_usage_logs` | 기능별 모델·토큰·성공 여부 기록 |

Flyway 마이그레이션은 이미 적용된 파일을 수정하지 않고 다음 버전 파일을 추가하는 방식으로 관리한다.

---

# 4. Spring Boot와 FastAPI 역할 분리

## Spring Boot

- JWT 인증 및 회원 식별
- 질문 요청 검증
- 대화 세션·메시지 저장
- 정책 문서 등록·조회
- FastAPI 호출
- LLM 사용량 성공·실패 로그 저장
- 사용자에게 표준 `ApiResponse` 반환

## FastAPI

- Spring Boot의 내부 요청 수신
- 질문 정규화 및 안전성 검사
- 관련 정책 청크 검색
- 프롬프트 구성
- OpenAI SDK 호출
- 답변, 참고 청크, 토큰 사용량 반환

브라우저가 FastAPI를 직접 호출하지 않고 반드시 Spring Boot를 거치게 해 인증과 기록 흐름을 한곳에서 관리한다.

---

# 5. 전체 데이터 흐름

```plain text
1. 사용자가 프런트 챗봇에서 질문 입력
2. 프런트가 Spring Boot API 호출
3. Spring Boot가 JWT로 회원 확인
4. 질문과 세션 정보를 준비해 FastAPI 호출
5. FastAPI가 관련 정책 청크 검색
6. 검색 결과와 질문으로 프롬프트 구성
7. OpenAI가 답변 생성
8. FastAPI가 답변과 사용량 반환
9. Spring Boot가 메시지와 LLM 사용량 저장
10. 프런트가 답변 표시
```

관련 정책을 찾지 못한 경우 임의로 답을 만들지 않고 관리자 문의 등록을 안내하도록 했다.

---

# 6. 환경변수와 내부 API 인증

Spring Boot와 FastAPI 사이에는 별도의 공유 API 키를 사용한다.

Spring Boot:

```properties
AGENT_BASE_URL=http://localhost:8000
AGENT_API_KEY=충분히_긴_공유_비밀값
```

FastAPI:

```properties
OPENAI_API_KEY=OpenAI_API_키
OPENAI_MODEL=gpt-4.1-mini
BACKEND_BASE_URL=http://localhost:8080
AGENT_API_KEY=Spring과_동일한_값
```

`OPENAI_API_KEY`는 OpenAI 호출용이고 `AGENT_API_KEY`는 Spring Boot와 FastAPI 사이의 내부 요청 인증용이므로 목적이 다르다.

---

# 7. 정리

- 문서를 작성하는 것 자체가 RAG는 아니며, 문서 검색 결과를 생성 모델에 제공하는 전체 흐름이 RAG다.
- 정책 문서는 프로젝트 고유 사실을 제공하는 근거 데이터다.
- Spring Boot는 보안과 저장, FastAPI는 검색과 생성에 집중한다.
- 관련 근거가 없을 때 답변을 추측하지 않는 것이 서비스 챗봇에서는 중요하다.
