# 관리자 회원·서비스 이용 통계 구현

관리자 대시보드에서 기간별 회원 현황과 서비스 이용률을 확인할 수 있도록 Spring Boot 통계 API와 프런트 화면을 구현했다. 조회 기간은 시작일 이상, 종료일 다음 날 0시 미만의 반개구간으로 통일했고, 데이터가 없는 날짜도 그래프에서 빠지지 않도록 0으로 채웠다.

---

# 1. 통계 조회 기간 처리

화면에서는 `LocalDate`로 시작일과 종료일을 받고, DB 조회에서는 `LocalDateTime`으로 변환한다.

```java
public record StatisticsPeriod(
        LocalDate startDate,
        LocalDate endDate
) {
    public LocalDateTime startAt() {
        return startDate.atStartOfDay();
    }

    public LocalDateTime endExclusive() {
        return endDate.plusDays(1).atStartOfDay();
    }
}
```

- `startAt`: 시작일 00:00:00
- `endExclusive`: 종료일 다음 날 00:00:00
- SQL 조건: `created_at >= startAt AND created_at < endExclusive`

`BETWEEN` 대신 반개구간을 사용하면 종료일의 23:59:59.999까지 별도로 계산하지 않아도 된다.

---

# 2. 회원 현황 통계

조회 항목은 다음과 같다.

| 항목 | 기준 |
| --- | --- |
| 현재 활성 회원 | 현재 `USER`, `ACTIVE` 상태인 회원 |
| 현재 비활성 회원 | 현재 `USER`, `INACTIVE` 상태인 회원 |
| 기간 내 신규 회원 | 선택 기간에 가입한 `USER` 회원 |
| 기간 내 비활성 처리 회원 | 상태 이력에서 `ACTIVE → INACTIVE`로 바뀐 고유 회원 |
| 일별 추이 | 날짜별 신규 가입 및 비활성 처리 회원 수 |

현재 상태 집계와 상태 변경 이력 집계는 의미가 다르다. 현재 활성 회원 수는 `members` 테이블을 조회하고, 기간 내 비활성 처리 수는 `member_status_histories`를 조회한다.

---

# 3. 서비스 이용 통계

선택 기간 동안 각 서비스를 실제로 이용한 고유 회원 수를 집계했다.

- 냉장고: `fridge_items.member_id`
- 장보기: `shopping_items.member_id`
- 레시피: `recipes.created_by`

```sql
SELECT 'recipe' AS service,
       COUNT(DISTINCT r.created_by) AS count
FROM recipes r
JOIN members m ON m.member_id = r.created_by
WHERE m.role = 'USER'
  AND m.status = 'ACTIVE'
  AND m.deleted_at IS NULL
  AND r.created_at >= :startAt
  AND r.created_at < :endExclusive
```

`'recipe' AS service`는 테이블의 컬럼을 읽는 것이 아니라 결과 행에 서비스 구분값을 붙이는 방식이다. 여러 서비스 결과를 `UNION ALL`로 합친 뒤 애플리케이션에서 서비스명별로 매핑할 수 있다.

---

# 4. 데이터가 없는 날짜를 0으로 채우기

DB의 `GROUP BY` 결과에는 데이터가 있는 날짜만 반환된다. 그래프의 날짜 축이 끊기지 않도록 조회 결과를 `Map<LocalDate, Long>`으로 바꾸고 전체 날짜를 순회했다.

```java
Map<LocalDate, Long> countByDate = projections.stream()
        .collect(Collectors.toMap(
                DailyCountProjection::getDate,
                DailyCountProjection::getCount
        ));
```

이후 `startDate`부터 `endDate`까지 날짜별로 `getOrDefault(date, 0L)`를 사용해 DTO를 생성한다.

---

# 5. 프런트 화면 구성

관리자 회원 화면을 다음 탭으로 분리했다.

1. 회원 현황
2. 회원 검색·관리
3. 서비스 이용률 상세

통계 화면에는 시작일·종료일 선택기와 최근 7일, 최근 30일, 전체 기간 버튼을 추가했다. 긴 기간을 일별 데이터로 모두 표시하면 축이 과밀해지므로 기간 길이에 따라 일·주·월 단위로 집계하는 기준도 필요하다.

---

# 6. 정리

- 화면의 날짜는 `LocalDate`, DB 조건은 반개구간 `LocalDateTime`으로 처리한다.
- 현재 상태와 기간 내 상태 변경 이력은 별개의 통계다.
- 고유 이용자는 `COUNT(DISTINCT member_id)`로 집계한다.
- 없는 날짜는 서비스 계층에서 0으로 채워 그래프 축을 유지한다.
- 관리자 통계는 조회 목적을 먼저 명확히 한 뒤 필요한 지표만 제공해야 한다.
