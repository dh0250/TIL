# 문의 Q&A 챗봇 연동, Swagger 문서화와 관리자 페이징

문의 Q&A 챗봇의 Spring Boot·FastAPI·프런트 연동을 마무리하고, 담당 API에 Swagger 설명을 추가했다. 관리자 사전재료 및 LLM 사용량 목록은 전체 데이터를 한 번에 반환하지 않도록 서버 페이징 방식으로 변경했다.

---

# 1. FastAPI 실행 구성

PyCharm에서는 기존 Conda 인터프리터를 선택하고 Uvicorn 모듈로 실행했다.

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

- `app.main`: `app/main.py` 모듈
- 마지막 `app`: 파일 안의 `FastAPI()` 객체
- `0.0.0.0`: 외부 인터페이스의 요청도 받을 수 있도록 바인딩
- `8000`: FastAPI가 사용할 포트
- `--reload`: 로컬 개발 중 코드 변경 시 자동 재실행

운영 Docker 이미지에서는 `--reload`를 사용하지 않는다.

---

# 2. 정책 문서 등록과 답변 확인

챗봇이 “정책에서 답변을 찾을 수 없습니다”라고만 응답한 원인은 LLM 자체가 아니라 검색할 정책 문서가 DB에 등록되지 않았기 때문이었다.

```plain text
Markdown 정책 문서
→ 관리자 문서 등록 API
→ inquiry_knowledge_documents 저장
→ 청크 분리
→ inquiry_knowledge_chunks 저장
→ 질문 시 관련 청크 검색
```

문서 수정 후에는 README만 바꾸는 것으로 끝나지 않는다. DB에 저장된 문서와 청크를 다시 등록하거나 갱신해야 실제 챗봇 답변에 반영된다.

---

# 3. 안전하지 않거나 무관한 질문 처리

초기 버전에서는 복잡한 회원별 차단 시스템을 추가하지 않고 최소 정책만 적용했다.

- 비속어 또는 명백히 무관한 질문은 AI를 호출하지 않는다.
- “서비스 이용과 관련된 질문을 입력해 주세요.”라고 안내한다.
- 위반 횟수 저장이나 일정 시간 차단은 구현하지 않는다.
- 일반 문의 작성 기능은 계속 사용할 수 있다.

불필요한 OpenAI 호출을 줄이고 사용자에게 챗봇의 역할을 명확하게 전달하는 데 목적이 있다.

# 4. Swagger/OpenAPI 문서화

Swagger UI에서 JWT를 입력할 수 있도록 OpenAPI 보안 스키마를 등록했다.

```java
new SecurityScheme()
        .type(SecurityScheme.Type.HTTP)
        .scheme("bearer")
        .bearerFormat("JWT")
```

컨트롤러에는 다음 내용을 중심으로 문서화했다.

- API 역할과 사용 주체
- 요청 파라미터와 요청 본문
- 정상 응답 구조
- 인증 필요 여부
- 주요 오류 응답

DTO의 `@Schema`에는 필드 설명과 예시를 넣었다. `example`은 실제 로직에 영향을 주지 않고 Swagger 화면에서 요청·응답 형태를 쉽게 이해하도록 보여주는 문서용 값이다.

---

# 5. 관리자 목록 서버 페이징

사전재료와 LLM 사용량 목록을 회원·레시피 목록과 동일하게 `Pageable` 기반으로 변경했다.

```plain text
GET /api/v1/admin/... ?page=0&size=20
```

서버 페이징 응답에는 일반적으로 다음 값이 포함된다.

- 현재 페이지 내용 `content`
- 현재 페이지 번호 `number`
- 페이지 크기 `size`
- 전체 데이터 수 `totalElements`
- 전체 페이지 수 `totalPages`
- 첫/마지막 페이지 여부

프런트만 데이터를 잘라 보여주면 서버는 여전히 전체 데이터를 조회한다. 데이터 증가를 고려하면 Repository, Service, Controller까지 함께 페이징해야 한다.

---

# 6. Enum 데이터 호환 문제

DB의 `llm_usage_logs.feature_type`에 Java Enum에 없는 값이 존재하면 다음 오류가 발생한다.

```plain text
No enum constant ... LlmFeatureType.FRIDGE_PHOTO_ANALYSIS
```

DB에 저장 가능한 문자열과 Java Enum 값은 반드시 일치해야 한다. 여러 AI 기능이 같은 로그 테이블을 사용한다면 기능 추가 시 Enum과 DB 제약조건을 함께 갱신해야 한다.

---

# 7. 정리

- RAG 답변 실패 시 먼저 정책 문서와 청크가 실제 DB에 등록됐는지 확인한다.
- Swagger 설정은 실행 로직이 아니라 API 사용 방법을 설명하는 문서 계층이다.
- 목록 데이터는 프런트가 아니라 백엔드부터 페이징해야 한다.
- 공유 테이블의 문자열 코드와 애플리케이션 Enum은 항상 같이 관리해야 한다.
