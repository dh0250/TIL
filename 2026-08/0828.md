# StudyOn 프론트엔드 React·Vite 전환과 Vercel 배포 설정

StudyOn 프론트엔드를 Next.js에서 React + Vite SPA로 전환했다. 화면과 기능은 유지하고 Next.js 전용 파일과 의존성만 정리했으며, Vercel이 이전 프레임워크 설정을 계속 사용해 발생한 배포 오류도 함께 해결했다.

---

# 1. Next.js에서 React + Vite로 전환한 이유

현재 서비스는 서버 렌더링, API Route, SEO가 핵심 요구사항이 아닌 예약 화면 중심의 SPA다. 그래서 Next.js의 App Router 구조를 유지할 이유가 크지 않았고, React + Vite로 단순하게 구성했다.

```text
Next.js
- app 디렉터리 기반 라우팅
- next 의존성 및 Next 전용 설정 필요

React + Vite
- 브라우저에서 동작하는 SPA
- Vite 개발 서버와 dist 정적 결과물 사용
```

UI를 새로 만들지는 않고 기존 JSX와 CSS를 최대한 유지했다. 프레임워크만 바꾸는 작업에서 디자인까지 함께 바꾸면 오류 원인을 분리하기 어려워지기 때문이다.

---

# 2. Vercel 배포 실패 원인

Vite로 전환한 뒤 Vercel 배포 로그에 다음 오류가 발생했다.

```text
No Next.js version detected.
Make sure your package.json has "next" ...
```

Vercel 프로젝트 설정이 예전 Next.js 프레임워크 프리셋으로 남아 있었기 때문이다. 코드의 `package.json`에서 `next`를 제거했는데도 Vercel이 Next.js 프로젝트로 빌드하려고 한 상황이었다.

해결 설정은 다음과 같다.

```text
Framework Preset: Vite
Build Command: npm run build
Output Directory: dist
Install Command: npm install
Root Directory: ./
```

설정을 저장한 뒤 다시 배포해 Vite 빌드가 정상적으로 완료되는 것을 확인했다.

---

# 3. 배포 프론트와 로컬 백엔드의 관계

Vercel에 올라간 프론트는 사용자의 브라우저에서 실행된다. 반면 `localhost:8080`으로 실행한 백엔드는 개발자 본인 컴퓨터에서만 접근 가능하다.

```text
로컬 프론트 (localhost:5173)
        ↓ 접근 가능
로컬 백엔드 (localhost:8080)

Vercel 프론트
        ↓ 인터넷에서 localhost:8080 접근 불가
로컬 백엔드
```

따라서 Vercel 사이트에서 스터디룸 목록이 비어 보이는 것은 백엔드가 AWS 등에 배포되지 않았기 때문이다. 로컬에서 연동을 확인할 때는 프론트와 백엔드를 모두 실행하고, 운영 연동은 백엔드의 공개 HTTPS 주소를 환경변수로 설정한 뒤 진행해야 한다.

---

# 4. 예약 화면의 API 데이터 처리

백엔드 API를 연결한 뒤 스터디룸 목록과 시간대는 더 이상 프론트의 데모 데이터만으로 표시되지 않는다.

```text
스터디룸 목록 API 응답
→ 선택한 방의 날짜별 가능 시간 API 호출
→ 가능한 시작 시간과 이용 시간 선택
→ 예약 생성 API 호출
```

백엔드가 아직 없는 상황이나 API 호출 실패 시에는 빈 목록이 표시될 수 있다. 이때 화면에 `NaN:00` 같은 잘못된 종료 시간이 나오지 않도록, 시작 시간이 없는 경우 종료 시간은 `00:00`으로 표시하고 선택은 계속 막는 방식으로 처리했다.

---

# 5. 정리

- StudyOn 프론트는 UI를 유지한 채 Next.js에서 React + Vite로 전환했다.
- Vercel의 Framework Preset도 Next.js에서 Vite로 바꿔야 한다.
- Vite 배포 결과물 폴더는 `dist`이며 빌드 명령은 `npm run build`다.
- Vercel에 배포한 프론트는 로컬 `localhost` 백엔드에 접근할 수 없다.
- 실제 운영 연동은 백엔드를 배포한 뒤 공개 주소와 CORS 설정을 추가해서 진행한다.
